For indexer operators and authors: what wallet-backend, stellar-etl and the kit's example indexer stored for each corpus entry, which entries the pinned current versions get wrong, and how three wallet-backend defects behave before and after their fixes. Read it to see which shapes your deployment of these indexers mishandles, or as a model of the result your own indexer gets through an adapter.

`xdrcheck replay` serves the entries' ledgers to an unmodified indexer through the input it already reads, lets it ingest, then has an adapter read back what it stored. The harness compares those rows with the facts a reference extractor took from the ledger's meta, never from the indexer. Inputs: `rpc`, the mock `getLedgers`; `sep54-dir`, the Galexie layout as a directory; `sep54-s3`, the Galexie layout from an object store.

## How to read a row

Each row is one indexer version on one input; each class column counts entries.

| Class | What the indexer did | What it means for you |
|---|---|---|
| **pass** | Stored every expected fact, and nothing forbidden | — |
| **mishandled** | Stored a wrong value or a forbidden fact, crashed, or hung | Rows in your database are wrong or the process died; a fix also needs the stored data repaired |
| **dropped** | Got past the ledger but left out a fact, the transaction or the ledger, without an error | Rows are missing and nothing told you |
| **halt** | Stopped at the ledger, or refused it without a gate the harness can confirm (`mishandled · halt` in the replay report) | Ingestion stops on mainnet when the shape arrives |
| **refused** | Refused the ledger at a gate it declares, wrote nothing, did not crash (`dropped · refused` in the replay report) | The safe behaviour for a shape the indexer does not support |
| **not-run** | The entry does not apply, or the indexer stopped at an earlier ledger | No result about this entry |
| **error** | Not an indexer result (adapter or harness fault) | A published summary holds none |

**Scope** `corpus` means the whole corpus ran; `known-divergences` means only the entries that declare a known divergence for that indexer ran. The full rules (eleven conditions, first match wins) are on [Replay harness](/reference/replay-harness).

## Limits

- These are results on corpus entries, not on all of mainnet. How often each shape occurs on pubnet is on [Mainnet scan](/results/mainnet-scan#prevalence-by-entry).
- Each indexer runs at the commit `pins.toml` names; a later commit has no row until it is pinned.
- Horizon has no row: its rig runs lake ledgers, not corpus entries ([Horizon rig](/reference/replay-harness#horizon-rig)).
