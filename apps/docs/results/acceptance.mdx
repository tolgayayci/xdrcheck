For anyone who wants to check that the kit itself works before relying on it. An acceptance check is one `make` target that exits 0 when the check holds and non-zero when it does not; the files it writes are the evidence. To use the kit you do not need this page: start from [Quickstart](/quickstart).

The states below are read from `evidence/results/acceptance.json`, which `make results-acceptance` writes from a full run. It holds 11 rows (10 met, 1 not met); a check with several cases has one row per case.

## States

- **met**: the artefact shows the check holds
- **not met**: anything is open, including what waits on people outside the build; the row names that action and keeps it apart from what the build must fix
- **missing**: a report the check needs is not under `reports/`
- **not recorded**: the check's make target was not run against these reports
- **proven in full CI**: only in the pull-request CI's table (`make acceptance-report-pr`): what that run checked holds, and the check's other runs are made only by the full CI (`.github/workflows/full.yml`), whose table is the check's verdict; a row that fails or lacks a report of its own pull-request run stays `not met` or `missing`

## Run them

After the one networked step (`make fetch`) and `make build`, every check runs offline; `OFFLINE=1` enforces it.

```sh
make verify OFFLINE=1        # every check at full size, then the table reports/acceptance.md
make verify-pr OFFLINE=1     # the fast forms the pull-request CI runs, then its table
```
