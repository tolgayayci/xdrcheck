For maintainers of the projects listed and for anyone running them: public incidents in which a Stellar reader (stellar-core tooling, an SDK, an XDR library or an indexer) met a shape it handled wrong, the corpus entries that hold each shape, and how far this kit goes in reproducing it. ## How to read the coverage column

| Coverage | Meaning |
|---|---|
| **reproduced** | A `make` target runs the affected project before and after its fix and shows the defect and then its absence |
| **run** | A target runs the project on the entries, and the entries declare its result |
| **checked** | A target checks the shape itself, without the affected project |
| **agreement** | Compared with a reference; not a reproduction |
| **input** | Corpus entries hold the shape; no reader of that project runs them here. Run them through your own reader |

## Limits

- The list is the set of public incidents the repository's README names, one row each; it is not every bug ever reported against these projects.
- An **input** row proves nothing about the affected project: no reader of it runs here.

The data is `evidence/results/known-defects.json` (`make results-known-defects`); the README's table names the upstream item of each row.
