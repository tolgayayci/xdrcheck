For SDK and XDR-library maintainers: how each pinned release of the Go, JavaScript, Python and Rust SDKs handles every corpus entry, and which entries the current release still gets wrong. After this page you can find your release's column, see what a divergence means for your users, and rerun any cell.

`xdrcheck conform` sends every corpus entry to a driver that runs one SDK at one pinned version (a **column**). The driver decodes the bytes, re-encodes them and reports the values it read; the runner compares them with the entry's expected values, which come from the bytes and never from an SDK. The public set has 21 columns; pull-request CI runs the 16 of the `pr` set (`drivers/sets.toml`).

## How to read a row

One cell per entry and column, folded over the entry's variants and conformance levels. A row of the tables below counts the cells of one column.

| Term | Meaning |
|---|---|
| **Agrees** | Every applicable variant and level gave the expected result: identical bytes after the round trip, the expected values, and the expected refusal where the entry must be refused |
| **Diverges** | The SDK gave a different result, and the entry declares that divergence for this SDK and version range. The run expects it: CI fails when a declared divergence stops reproducing, and when an undeclared one appears |
| **Not run** | No variant or level of the entry applies to the column (an API the SDK lacks, a type the release predates, a level the driver does not run). Not run is not a pass |
| **required** | The current release of each SDK family; the `required` set gates CI |
| **historical** | An earlier release kept as a regression pin, including the releases before a fix so the fix stays proven |
| **extra** | A release run in the public set only, or a reference column such as stellar-core |
| **In the PR set** | Whether pull-request CI runs this column |

A divergence on your release means one of these, depending on the entry: your decoder accepts bytes stellar-core would never emit, or refuses bytes it does emit; a round trip changes the bytes; or a value your users read (an address, an amount, an ID, a map order) differs from what the ledger holds. The entry's manifest names the [finding](/results/findings) that describes it. Not every divergence is a defect: a refusal that comes from a column's decode profile (the Rust `limits-default` limits) is declared with that profile and is the profile working as documented.

## Limits

- A cell is a result on the corpus only. An SDK that agrees on every entry can still mishandle a shape the corpus does not hold.
- The matrix is a snapshot of the pinned releases at corpus version `30.0.0-dev`; a newer release has no column until it is pinned in `pins.toml`.
- The Python SDK is a community SDK; its columns run in the same way as the others.

The data is `evidence/results/conformance-matrix.json` (`make results-conformance`); the rules are on [Conformance rules](/reference/driver-protocol#conformance-rules) and the design on [Conformance](/architecture/conformance).
