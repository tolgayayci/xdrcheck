For authors and operators of software that reads Stellar ledgers into a store: wallet-backend, stellar-etl,
Horizon or your own. After this page you have replayed the corpus through an adapter, know how to point the
adapter at your indexer, and can run the same replay on every pull request.

The replay harness serves corpus ledgers to your unmodified indexer through an input it already reads, waits for
it to ingest them, and compares what it stored with each entry's expected values. Your indexer talks to the
harness through a small adapter: a program that speaks JSON lines over stdin and stdout. How that works step by
step is on [Replay](/architecture/replay).

<Steps>
  <Step title="Build the kit once">

    On Linux with [mise](https://mise.jdx.dev) and [rustup](https://rustup.rs):

    ```sh
    mise install
    make toolchain && make fetch-replay && make build
    export PATH="$PWD/bin:$PATH"
    ```

    `make fetch-replay` is the only networked step; everything after it runs offline.

  </Step>
  <Step title="See a failing indexer first">

    ```sh
    make demo
    ```

    The demo replays the fee-bump and muxed-account entries through a small indexer with one planted bug (it
    skips failed transactions). The report, `reports-demo/REPORT.md`, shows each entry it got wrong, what the
    ledger holds against what it stored, and the command that replays that entry alone. Expected output is on
    [Quickstart](/quickstart).

  </Step>
  <Step title="Replay the whole corpus through the adapter template">

    ```sh
    xdrcheck replay --adapter bin/minimal --target-version 0.1.0 --input sep54-dir --report reports/minimal
    ```

    `--input` is how the ledgers reach the indexer: `sep54-dir` (the SEP-54 layout in a directory, no Docker),
    `sep54-s3` (the same layout behind an S3 API, needs Docker) or `rpc` (a mock stellar-rpc `getLedgers`). The
    run ends with one line: rows per class, failures and harness faults. The template must pass.

  </Step>
  <Step title="Point the adapter at your indexer">

    Copy the template into your own module and fill in the places marked `REPLACE`: how to start your indexer on
    the harness's ledgers, and how to read back what it stored.

    - Go: [Go indexer](/guides/go-indexer) (`go/adapters/minimal`).
    - Any other language: [Indexer in any language](/guides/any-language-indexer) (`examples/adapter-ts`).
    - The messages in full: [Adapter protocol](/reference/adapter-protocol).
    - Every observation kind in one adapter: [Baseline adapter](/reference/replay-harness#baseline-adapter). The
      wallet-backend adapter is `go/adapters/walletbackend`.

  </Step>
  <Step title="Run it on every pull request">

    The GitHub Action runs the same replay from a pinned corpus release, with an expected-failure list that
    keeps known failures from failing the build until they are fixed: [CI recipes: replay](/guides/ci#2-indexer-authors-replay).

  </Step>
</Steps>

## Reading a result

Each entry variant comes out in one class:

| Class | Your indexer |
|---|---|
| `pass` | stored every expected fact |
| `mishandled · crash`, `hang`, `halt`, `wrong_value` | crashed, timed out, stopped at the ledger, or stored a wrong or forbidden value |
| `dropped · silent`, `partial`, `refused` | went past the ledger holding nothing for it, missed a fact, or refused it at a gate it declared |
| `not_applicable`, `not_reached` | was not asked: outside the envelope its adapter declared, or stopped at an earlier ledger |
| `harness_fault` | nothing: the adapter or the harness failed, and the row says which |

The full list of classes and how each is decided is on [Replay, step 4](/architecture/replay#step-4-classification).
A run exits 0 when no row fails, 1 when one does, and 2 when the harness itself could not run. Exit 2 usually
means a tool was not built (`make build`) or the adapter's command line is wrong (`--selftest` checks it).

## Limits

- The harness, the rigs and `xdrcheck replay` run on Linux only.
- A verdict covers only the observation kinds your adapter reports. The template reports receipts and
  transactions; participants, state changes, movements and addresses are added kind by kind.
- The corpus holds rare shapes, not traffic volume. For real mainnet ledgers through wallet-backend, stellar-etl or
  Horizon, use the service rigs: [Replay real ledgers](/reference/replay-target).
