## What it reports

`v, _ := f(…)`, where `f` returns an error as its last result and is a function of the SDK module (`xdr`,
`strkey`, `amount`, `ingest`, `processors`, …), `strconv`, `encoding/hex`, `encoding/base64`, `encoding/json`,
`math/big` or `time` (or is `big.Int.SetString`, with its ok result), and `v` is later stored in the same
function: part of a composite literal, assigned to a field, map entry or slice element, appended, or passed to a
database call or a builder. A variable tested in a condition first (`if v == "" { … }`) counts as checked.

Not reported: `strkey.Encode` of a 32-byte array (an ID; it cannot fail), and a parse of a string field of an SDK
struct (the SDK formatted it).

## Why it matters

A discarded error leaves the zero value in its place: an empty address, amount 0, a zero ID. Stored, it cannot be
told apart from a real value, and nothing records that the row is wrong.

## Limits

A discarded `ok` of an xdr `Get<Arm>()` accessor is not reported: one wide row per union, with the other arms left
at zero, is a common and deliberate layout (XDR105 covers arm reads that panic). Uses in another function are not
followed.
