## What it reports

A `switch` over an enum of the SDK's `xdr` package (`OperationType`, `LedgerEntryType`, `ScValType`, …) whose
cases write rows (append, assign to a field or map entry, build a composite literal, call a builder or database
method) and that has no default, or a default that panics or exits. The message lists the values the SDK declares
that the switch does not handle; when it handles all of them, a value a later protocol adds still falls through.

This rule is opt-in.

## Why it matters

Protocol upgrades add enum values: operations, entry types, value types, address kinds. A closed switch drops the
new value without a trace, or halts the job on it, on upgrade day. A default that records the unknown value (an
error the operator sees, a counter, a typed skip) turns a silent loss into a decision.

## Limits

Many switches handle a subset on purpose (only the entry types a table holds). The rule cannot tell that from an
omission, which is why it is opt-in.
