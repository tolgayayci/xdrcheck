## What it reports

- An error for any use of go-xdr's `DecodeUnlimitedDepth`, or a `DecodeOptions` literal whose `MaxDepth` is an
  unlimited sentinel.
- A warning for `xdr.Unmarshal` or `xdr.UnmarshalWithOptions` on a reader without a `Len() int` method (a network
  body, a decompression stream) when `MaxInputLen` is not set.

`xdr.SafeUnmarshal…` with its defaults is not reported: depth 1500, the input length set, pre-allocation capped.

## Why it matters

The decoder's limits are what bound everything a reader does afterwards. With the depth limit disabled, one
deeply nested value exhausts the stack; with no input length, a length prefix can claim more data than the
stream holds. The go-xdr default of 1500 depth units admits 749 nested vector levels, more than stellar-core
admits into a ledger, so the defaults are safe for ledger meta.
