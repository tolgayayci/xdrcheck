# Independent reproduction reviews

One file per finding record, `findings/review/<id>.json`, written by a reviewer who did not produce the record or
its report rows. The reviewer works from the record alone (target, versions, entries, report rows, evidence
paths), re-runs it with the kit's tools on a clean checkout, and either accepts the record or returns it with the
step that failed. This is the reproduction step of the findings lifecycle (`findings/README.md`); it happens
before any issue text is drafted.

The record itself carries the outcome in its `reproduction` block (`by: independent-reviewer`, the date, a short
method that points here, and `reproduced` or `not-reproduced`). Nothing else in the record is changed by the
review: a record that needs a correction is returned, and the author makes the change.

The finding-record schema has no field for the review itself, so this directory uses the small format below. It is
not one of the frozen schemas under `corpus/schema/`.

## Format: `xcc.finding-review/v1`

```json
{
  "schema": "xcc.finding-review/v1",
  "finding": "F-0012",
  "reviewer": "independent-reviewer",
  "date": "2026-11-12",
  "record_state": "duplicate-of",
  "target": "stellar/wallet-backend",
  "reproduction": {
    "result": "reproduced",
    "offline": true,
    "steps": [
      {
        "command": "make verify-replay OFFLINE=1",
        "observed": "what the run showed for this record's rows",
        "ok": true
      }
    ],
    "report_rows": { "listed": 1, "found_failing": 1, "not_found": [], "not_failing": [] }
  },
  "checks": {
    "upstream": { "url": "https://github.com/…", "matches_rows": true, "state_seen": "closed (merged …)", "note": "" },
    "links": { "dangling": [] },
    "resolution": "for not-a-defect records: whether the stated reason holds at the cited commit"
  },
  "notes": ["anything the author should know that does not block the record"],
  "verdict": "accepted",
  "failing_step": null
}
```

| Field | Meaning |
|---|---|
| `reproduction.result` | `reproduced` when the defect the record describes is shown again, with the class, verdict or rule the record states, on its entries at its versions; otherwise `not-reproduced`. Listed rows that do not fail again are named under `report_rows.not_found` or `not_failing`, and make the verdict `returned` |
| `reproduction.offline` | the steps ran under `scripts/offline-run.sh` (or a `make` target with `OFFLINE=1`) after `make fetch` |
| `reproduction.steps` | the commands, from the repository root, in the order they were run, and what each showed |
| `reproduction.report_rows` | how many of the record's `evidence.report_rows` were found failing in the new reports |
| `checks.upstream` | whether the upstream item (read-only) is the one that records this defect, and its state when checked |
| `checks.links` | evidence and transcript paths or URLs in the record that do not resolve |
| `checks.resolution` | for `not-a-defect` records, whether the reviewer agrees with the stated reason |
| `verdict` | `accepted`: reproduced and the record can stand as written. `returned`: something in the record must change first; `failing_step` names it |

Reports written by the reproduction runs are not kept in the repository; they are regenerated by the commands in
`steps`.
