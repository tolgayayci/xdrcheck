Run Ingestion service

Usage:
  wallet-backend ingest [flags]

Flags:
      --admin-port int                         Port for admin server exposing pprof endpoints at /debug/pprof. Leave unset to disable. (ADMIN_PORT)
      --archive-url string                     Archive URL for history archives (ARCHIVE_URL) (default "https://history.stellar.org/prd/core-testnet/core_testnet_001/")
      --backfill-batch-size int                Number of ledgers per batch during backfill. Defaults to 250. Lower values reduce RAM usage at cost of more DB transactions. (BACKFILL_BATCH_SIZE) (default 250)
      --backfill-db-insert-batch-size int      Number of ledgers to process before flushing buffer to DB during backfill. Defaults to 100. Lower values reduce RAM usage at cost of more DB transactions. (BACKFILL_DB_INSERT_BATCH_SIZE) (default 100)
      --backfill-workers int                   Maximum concurrent workers for backfill processing. Defaults to number of CPUs. Lower values reduce RAM usage at cost of throughput. (BACKFILL_WORKERS)
      --blend-price-interval string            Interval between Blend v2 oracle price snapshot passes (Go duration string, e.g. "60s"). 0 disables the snapshot task. (BLEND_PRICE_INTERVAL) (default "60s")
      --checkpoint-frequency int               Checkpoint frequency for history archive (number of ledgers between checkpoints). Use 64 for production usage, 8 for integration tests with accelerated time. (CHECKPOINT_FREQUENCY) (default 64)
      --chunk-interval string                  TimescaleDB chunk time interval for hypertables. Only affects future chunks. Uses PostgreSQL INTERVAL syntax. (CHUNK_INTERVAL) (default "1 day")
      --compression-compress-after string      How long after a chunk is closed before it becomes eligible for compression. Lower values reduce the number of uncompressed chunks. Empty skips configuration. Uses PostgreSQL INTERVAL syntax. (COMPRESSION_COMPRESS_AFTER)
      --compression-max-chunks int             Maximum chunks compressed per compression job run (maxchunks_to_compress). 0 leaves the job's current setting unchanged. Set to a small value (e.g. 10) during backfill to prevent job run overlap. (COMPRESSION_MAX_CHUNKS)
      --compression-schedule-interval string   How frequently the TimescaleDB compression policy job checks for chunks to compress. Does not change which chunks are eligible (that's controlled by compress_after). Empty skips configuration. Uses PostgreSQL INTERVAL syntax. (COMPRESSION_SCHEDULE_INTERVAL)
      --database-url string                    Database connection URL. (DATABASE_URL) (default "postgres://postgres@localhost:5432/wallet-backend?sslmode=disable")
      --datastore-bucket-path string           Datastore bucket and path holding exported ledgers (S3 destination_bucket_path), e.g. aws-public-blockchain/v1.1/stellar/ledgers/pubnet. Required when ledger-backend-type=datastore. (DATASTORE_BUCKET_PATH)
      --datastore-buffer-size uint32           Number of ledger files to prefetch into the datastore read buffer. (DATASTORE_BUFFER_SIZE) (default 100)
      --datastore-endpoint-url string          Custom S3 endpoint URL (e.g. for minio). Leave empty to use the default AWS endpoint. (DATASTORE_ENDPOINT_URL)
      --datastore-files-per-partition uint32   Files per datastore partition. 0 reads the schema from the datastore manifest (.config.json). (DATASTORE_FILES_PER_PARTITION)
      --datastore-ledgers-per-file uint32      Ledgers per datastore file. 0 reads the schema from the datastore manifest (.config.json). (DATASTORE_LEDGERS_PER_FILE)
      --datastore-num-workers uint32           Number of concurrent workers downloading ledger files from the datastore. (DATASTORE_NUM_WORKERS) (default 10)
      --datastore-region string                AWS region of the datastore bucket. Leave empty to use the AWS default chain. (DATASTORE_REGION) (default "us-east-2")
      --datastore-retry-limit uint32           Maximum retries for a failed (transient) ledger-file download. (DATASTORE_RETRY_LIMIT) (default 3)
      --datastore-retry-wait string            Wait between datastore download retries (Go duration string, e.g. "5s"). (DATASTORE_RETRY_WAIT) (default "5s")
      --db-max-conn-idle-time string           Maximum idle time for a DB connection (Go duration string, e.g. "10s"). (DB_MAX_CONN_IDLE_TIME) (default "10s")
      --db-max-conn-lifetime string            Maximum lifetime of a DB connection (Go duration string, e.g. "5m"). (DB_MAX_CONN_LIFETIME) (default "5m0s")
      --db-max-conns int                       Maximum number of connections in the DB pool. (DB_MAX_CONNS) (default 12)
      --db-min-conns int                       Minimum number of idle connections kept in the DB pool. (DB_MIN_CONNS) (default 5)
      --end-ledger int                         Last ledger of a backfill range (ingestion-mode=backfill). Live mode rejects this flag. (END_LEDGER)
      --get-ledgers-limit int                  The limit for the number of ledgers to fetch from the RPC in a single "getLedgers" call. In production, don't go above 10 if unless your RPC instance has the MAX_GET_LEDGERS_EXECUTION_DURATION >= 5s. (GET_LEDGERS_LIMIT) (default 10)
  -h, --help                                   help for ingest
      --ingest-server-port int                 The port for the ingest server. (INGEST_SERVER_PORT) (default 8002)
      --ingestion-mode string                  What mode to run ingestion in - live or backfill (INGESTION_MODE) (default "live")
      --ledger-backend-type string             Where ledgers are read from. 'rpc' (default) streams them from the RPC at rpc-url; 'datastore' reads them from the S3 data lake at datastore-bucket-path. (LEDGER_BACKEND_TYPE) (default "rpc")
      --live-persist-max-batch-size int        Maximum consecutive ledgers coalesced into one persist commit when live ingestion falls behind. The default 1 persists every ledger in its own commit — right for networks whose close time comfortably exceeds the persist time; raise it on high-TPL/short-block deployments to amortize inserts across a backlog at the cost of coarser crash recovery and visibility latency under load. The pipeline holds up to 2× this value + 1 ledger buffers at peak — check memory headroom before raising it under GOMEMLIMIT. (LIVE_PERSIST_MAX_BATCH_SIZE) (default 1)
      --log-level string                       The log level used in this project. Options: "TRACE", "DEBUG", "INFO", "WARN", "ERROR", "FATAL", or "PANIC". (LOG_LEVEL) (default "INFO")
      --network-passphrase string              Stellar Network Passphrase to connect. (NETWORK_PASSPHRASE) (default "Test SDF Network ; September 2015")
      --retention-period string                TimescaleDB data retention period. Chunks older than this are automatically dropped. Empty disables retention. Uses PostgreSQL INTERVAL syntax. (RETENTION_PERIOD)
      --rpc-url string                         The URL of the RPC Server. (RPC_URL) (default "http://localhost:8000")
      --start-ledger int                       First ledger of a backfill range (ingestion-mode=backfill). Live mode resumes from the stored cursor and rejects this flag. (START_LEDGER)
      --tx-hash-maintenance-interval string    How often the transaction_hashes maintenance jobs run. A run deletes the lookup rows of 30-day periods that closed before both the oldest retained transaction and the retention cutoff (no retention policy: no delete), then recompresses the whole lookup table. Set it so the rows written between runs stay in the low hundreds of millions. A daily run keeps the rowstore parts of the 1,024 chunks bounded without tuning: about 4 minutes and 2 GB of WAL on one worker at today's mainnet rate, about 55 minutes on eight workers at 10,000 transactions per second (864 million rows a day). Uses PostgreSQL INTERVAL syntax. (TX_HASH_MAINTENANCE_INTERVAL) (default "1 day")
      --tx-hash-maintenance-workers int        How many transaction_hashes maintenance jobs run at once, each over its own share of the chunks; a run finishes about that many times faster. Use 8 at 10,000 transactions per second. Each job is one TimescaleDB background worker and counts against timescaledb.max_background_workers. (TX_HASH_MAINTENANCE_WORKERS) (default 1)
